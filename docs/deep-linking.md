# Referral Deep Linking

Cross-platform deep linking for the referral flow. When a user shares their referral link, recipients can tap it to open the app directly (or be redirected to the store if not installed).

## How It Works

```
User A shares referral link
        │
        ▼
  https://api.vyzi.app/r/AB3KX7WN
        │
        ├── App installed? ──► YES ──► App opens via Universal/App Link
        │                                │
        │                                ├── Logged in?  ──► YES ──► Dialog: "Referral Not Available"
        │                                │
        │                                └── Not logged in? ──► Registration screen (code pre-filled)
        │
        └── App NOT installed? ──► Landing page loads in browser
                                       │
                                       ├── Shows referral code + "Copy" button
                                       ├── Store redirect button (Play Store / App Store)
                                       └── Auto-redirects to store after 3 seconds
                                             │
                                             ▼
                                       User installs app ──► First launch
                                             │
                                             └── If code was copied to clipboard:
                                                   Registration screen (code available via paste)
```

## URL Format

**Share link**: `{BACKEND_DOMAIN}/r/{REFERRAL_CODE}`

Example: `https://api.vyzi.app/r/AB3KX7WN`

The link is generated by the backend when a user calls `GET /api/v1/referrals/my-code`. The format changed from the old `{FRONTEND_URL}/register?ref={CODE}` to this backend-served URL so the same domain can serve:
1. The `.well-known` verification files (for App Links / Universal Links)
2. The HTML landing page fallback (for when the app is not installed)

## User Flows

### Flow 1: App Installed + User Logged In

1. User taps referral link
2. OS intercepts the URL (App Link / Universal Link) and opens the app
3. `DeepLinkService` receives the URI, extracts the referral code
4. Checks auth state via `StorageService` — user is logged in
5. Shows an `AlertDialog`:
   - **Title**: "Referral Not Available"
   - **Body**: "This referral link cannot be applied because you are already logged in. Referral rewards are only available for new accounts created using a referral link."
   - **Button**: "OK"
6. User stays on their current screen

### Flow 2: App Installed + User NOT Logged In

1. User taps referral link
2. OS intercepts the URL and opens the app
3. `DeepLinkService` receives the URI, extracts the referral code
4. Checks auth state — user is NOT logged in
5. Navigates to the registration screen (`AppRoutes.signUpScreen`)
6. Referral code is pre-filled in the "Referral Code" field (editable)
7. User completes registration
8. Backend validates and applies the referral code during `POST /api/v1/auth/register`

### Flow 3: App NOT Installed (Deferred Deep Link)

1. User taps referral link
2. App is not installed — browser opens the landing page at `/r/{CODE}`
3. Landing page shows:
   - Referral code with a "Copy" button (copies to clipboard)
   - Platform-specific download button (Play Store or App Store)
   - Auto-redirects to the store after 3 seconds
4. User installs the app from the store
5. On first launch, user can paste the referral code into the registration form
6. User completes registration with the referral code applied

## Backend Endpoints

Three endpoints served at the root level (excluded from the `api/v1` global prefix):

### GET /.well-known/assetlinks.json

Android App Links verification file. Android fetches this at app install time to verify the app is authorized to handle URLs from this domain.

**Response** (200):
```json
[
  {
    "relation": ["delegate_permission/common.handle_all_urls"],
    "target": {
      "namespace": "android_app",
      "package_name": "com.vyzi",
      "sha256_cert_fingerprints": ["XX:XX:XX:..."]
    }
  }
]
```

Returns an empty array `[]` if `ANDROID_SHA256_FINGERPRINT` is not configured.

### GET /.well-known/apple-app-site-association

iOS Universal Links verification file. Apple's CDN fetches this to verify the app is authorized to handle URLs from this domain.

**Response** (200):
```json
{
  "applinks": {
    "apps": [],
    "details": [
      {
        "appID": "{APPLE_TEAM_ID}.com.homecraft.service",
        "paths": ["/r/*"]
      }
    ]
  }
}
```

### GET /r/:code

HTML landing page for referral links. Serves as both the deep link target and the fallback page when the app is not installed.

**Behavior:**
- Validates the referral code against the database
- Detects platform from `User-Agent` header (Android, iOS, or desktop)
- Returns a branded HTML page with:
  - The referral code (with copy-to-clipboard button) if valid
  - An error message if the code is invalid/expired
  - Platform-specific store download button
  - Auto-redirect to store after 3 seconds (mobile only)
  - Both store links for desktop browsers

**Response**: `text/html` with a custom Content-Security-Policy header allowing inline styles and scripts.

## Flutter Implementation

### DeepLinkService

**File**: `bill_saving_app/lib/core/services/deep_link_service.dart`

Singleton service initialized in `main.dart`, registered via `Get.put<DeepLinkService>()`.

Uses the `app_links` package to handle:
- **Cold start**: `_appLinks.getInitialLink()` — app opened via deep link when not running
- **Warm start**: `_appLinks.uriLinkStream` — link received while app is already running

**Key methods:**

| Method | Purpose |
|--------|---------|
| `init()` | Initialize link listeners + check stored deferred code |
| `markSplashCompleted()` | Called after splash screen navigates; enables warm-start routing |
| `showReferralNotAvailableDialog()` | Shows dialog for logged-in users |
| `clearPendingReferralCode()` | Clears code from memory and storage |
| `storeDeferredReferralCode(code)` | Persists code for deferred deep linking |

**Initialization order** (in `main.dart`):
```
Firebase → CacheService → StorageService → DeepLinkService → LanguageController → runApp
```

### Splash Screen Integration

**File**: `bill_saving_app/lib/features/splash/spalsh_screen.dart`

The splash screen's `_checkUserSession()` method checks for a pending referral code after the 3-second delay:

```
Wait 3s → Check auth state → Check pending referral code
   │
   ├── Logged in + referral code → Navigate to navbar → Show dialog
   ├── Not logged in + referral code → Navigate to registration (code pre-filled)
   └── No referral code → Normal flow (navbar or onboarding)
```

### Registration Screen

**File**: `bill_saving_app/lib/features/auth/create_account.dart`

No changes were needed. The screen already reads `Get.arguments?['referralCode']` in `initState()` and pre-fills the referral code text field. The field remains editable.

## Platform Configuration

### Android — App Links

**File**: `bill_saving_app/android/app/src/main/AndroidManifest.xml`

An intent-filter with `android:autoVerify="true"` is added to the main activity:

```xml
<intent-filter android:autoVerify="true">
    <action android:name="android.intent.action.VIEW"/>
    <category android:name="android.intent.category.DEFAULT"/>
    <category android:name="android.intent.category.BROWSABLE"/>
    <data
        android:scheme="https"
        android:host="api.vyzi.app"
        android:pathPrefix="/r/"/>
</intent-filter>
```

- `autoVerify="true"` tells Android to fetch `/.well-known/assetlinks.json` at install time
- Only URLs matching `https://api.vyzi.app/r/*` are intercepted
- The host **must match** the `BACKEND_DOMAIN` environment variable

### iOS — Universal Links

**File**: `bill_saving_app/ios/Runner/Runner.entitlements`

The associated domains entitlement is added:

```xml
<key>com.apple.developer.associated-domains</key>
<array>
    <string>applinks:api.vyzi.app</string>
</array>
```

- Apple fetches `/.well-known/apple-app-site-association` from this domain via its CDN
- The domain **must match** the `BACKEND_DOMAIN` environment variable
- The `appID` in the AASA file must be `{APPLE_TEAM_ID}.{BUNDLE_ID}`

## Environment Variables

Add these to the backend `.env` file:

| Variable | Description | Example |
|----------|-------------|---------|
| `BACKEND_DOMAIN` | Public HTTPS URL of the backend server | `https://api.vyzi.app` |
| `ANDROID_SHA256_FINGERPRINT` | SHA256 fingerprint of the Android signing certificate | `AA:BB:CC:...` (32 hex pairs) |
| `APPLE_TEAM_ID` | Apple Developer Team ID (10 characters) | `ABCDE12345` |
| `PLAY_STORE_URL` | Google Play Store listing URL | `https://play.google.com/store/apps/details?id=com.vyzi` |
| `APP_STORE_URL` | Apple App Store listing URL | `https://apps.apple.com/app/vyzi/id1234567890` |

## Remaining Setup Steps

These steps must be completed manually before deep linking works in production:

### 1. Set Environment Variables on the Backend

Add all five deep linking env vars to the production `.env` or hosting platform config:

```bash
BACKEND_DOMAIN=https://api.vyzi.app       # Your actual backend domain
ANDROID_SHA256_FINGERPRINT=AA:BB:CC:...    # From step 2
APPLE_TEAM_ID=ABCDE12345                   # From step 3
PLAY_STORE_URL=https://play.google.com/store/apps/details?id=com.vyzi
APP_STORE_URL=https://apps.apple.com/app/vyzi/id1234567890
```

### 2. Get the Android SHA256 Signing Certificate Fingerprint

The fingerprint must match the keystore used to sign the APK/AAB.

**For the debug keystore** (testing):
```bash
keytool -list -v \
  -keystore ~/.android/debug.keystore \
  -alias androiddebugkey \
  -storepass android \
  -keypass android \
  | grep SHA256
```

**For the release keystore** (production):
```bash
keytool -list -v \
  -keystore /path/to/your-release-key.jks \
  -alias your-key-alias \
  | grep SHA256
```

**If using Google Play App Signing** (recommended):
1. Go to Google Play Console → Your App → Setup → App signing
2. Copy the SHA256 fingerprint from the "App signing key certificate" section

Set the output as `ANDROID_SHA256_FINGERPRINT` in your `.env`.

### 3. Get the Apple Team ID

1. Go to [Apple Developer Portal](https://developer.apple.com/account)
2. Click "Membership Details" (or look in the top-right corner)
3. Copy the "Team ID" (10 characters, e.g., `ABCDE12345`)

Set this as `APPLE_TEAM_ID` in your `.env`.

### 4. Enable Associated Domains in Apple Developer Portal

1. Go to [Apple Developer Portal](https://developer.apple.com/account) → Certificates, Identifiers & Profiles → Identifiers
2. Find the App ID: `com.homecraft.service`
3. Click on it → scroll to "Associated Domains"
4. Enable the checkbox
5. Click "Save"

Without this step, iOS Universal Links will not work.

### 5. Update the Android Manifest Host (if domain differs)

If your production backend domain is NOT `api.vyzi.app`, update the host in:

**File**: `bill_saving_app/android/app/src/main/AndroidManifest.xml`
```xml
<data
    android:scheme="https"
    android:host="YOUR_ACTUAL_DOMAIN"
    android:pathPrefix="/r/"/>
```

### 6. Update the iOS Entitlements (if domain differs)

If your production backend domain is NOT `api.vyzi.app`, update:

**File**: `bill_saving_app/ios/Runner/Runner.entitlements`
```xml
<string>applinks:YOUR_ACTUAL_DOMAIN</string>
```

### 7. Publish the App to Stores

The Play Store and App Store URLs in the landing page will return 404 until the app is published. The deep link landing page will still work but the store buttons will lead to dead links.

### 8. Verify the HTTPS Configuration

Both `.well-known` endpoints **must** be served over HTTPS with a valid SSL certificate. Self-signed certificates will not work.

Verify after deployment:
```bash
curl -I https://YOUR_DOMAIN/.well-known/assetlinks.json
curl -I https://YOUR_DOMAIN/.well-known/apple-app-site-association
```

Both should return `200 OK` with `Content-Type: application/json`.

### 9. Verify Android App Links

After installing the app on an Android device:
```bash
# Check if the domain is verified
adb shell pm get-app-links com.vyzi

# Force re-verify (if needed)
adb shell pm verify-app-links --re-verify com.vyzi
```

Expected output should show `verified` for `api.vyzi.app`.

### 10. Test the Apple AASA File

Use Apple's validator (requires macOS with Xcode or the online validator):
```bash
# Check AASA from Apple's CDN (after domain setup)
curl -v https://app-site-association.cdn-apple.com/a/v1/YOUR_DOMAIN
```

Note: Apple aggressively caches the AASA file. After deploying changes, it can take **up to 24 hours** to propagate. During development, add `?mode=developer` to the associated domain in the entitlements to bypass the CDN:
```xml
<string>applinks:api.vyzi.app?mode=developer</string>
```
Remove `?mode=developer` before releasing to production.

## Troubleshooting

### Android: Link opens in browser instead of app

- Verify `assetlinks.json` is accessible over HTTPS: `curl https://YOUR_DOMAIN/.well-known/assetlinks.json`
- Verify the SHA256 fingerprint matches your signing key
- Run `adb shell pm verify-app-links --re-verify com.vyzi`
- Ensure the device has a data connection (verification happens at install time)
- Check that the host in `AndroidManifest.xml` matches `BACKEND_DOMAIN` exactly

### iOS: Link opens in browser instead of app

- Verify AASA file is accessible: `curl https://YOUR_DOMAIN/.well-known/apple-app-site-association`
- Verify `APPLE_TEAM_ID` is correct and `appID` format is `{TEAM_ID}.com.homecraft.service`
- Enable Associated Domains capability in Apple Developer Portal for `com.homecraft.service`
- Check entitlements file has `applinks:YOUR_DOMAIN`
- Apple caches AASA aggressively — wait up to 24 hours or use `?mode=developer`
- Long-press the link on iOS to see "Open in VYZI" option

### Landing page returns 404

- Verify the deep link routes are excluded from the global prefix in `main.ts`
- Check that `DeepLinkModule` is imported in `app.module.ts`
- Verify the backend is deployed and running

### Referral code not pre-filled on registration

- Check `DeepLinkService` is initialized before the splash screen runs
- Verify `StorageService` is available via `Get.find<StorageService>()`
- Check console logs for `DeepLinkService:` error messages
- Ensure the URL matches the `/r/{code}` pattern (exactly 2 path segments)
